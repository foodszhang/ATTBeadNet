# Traditional bead-detection baselines

`scripts/traditional_baselines.py` provides multisize-compatible reimplementations of two conventional, non-deep-learning bead-detection baselines. They preserve the intended method families and evaluation interface; they are not byte-for-byte restorations of archived ImageJ macros or an original SVM training environment.

## Methods

- `imagej_like`: percentile normalization, white top-hat background suppression, Gaussian smoothing, Otsu/intensity thresholding, morphology, connected-component area/circularity filtering, and supplementary Laplacian-of-Gaussian blob detection. Fixed component-size and LoG-scale rules assign detections to the `1.0` and `2.8` classes.
- `svm_patch`: white top-hat local-maximum candidates followed by a standardized RBF-SVM patch classifier. The three labels are background, `1.0`, and `2.8`; positive samples come from annotated centers and negative samples are candidate peaks more than six pixels from every annotation.

Both methods use the repository's class-aware Hungarian center matching and emit per-image metrics, pooled aggregate metrics, confusion matrices, predicted centers, optional overlays, and a `run_metadata.json` record.

## Validation protocol

- Splits are resolved at the source-image level from `manifest.csv`. The default protocol trains `svm_patch` on `train_pool` and evaluates both methods on `internal_val`.
- The runner fails before fitting or evaluation when required directories, manifest columns, split members, RF images, or class masks are missing. It also rejects train/validation source-image overlap for `internal_val`.
- Precision, recall, and F1 in `metrics_summary.csv` are pooled from summed TP/FP/FN counts, using a 3-pixel class-aware matching radius by default.
- `imagej_like` has no fitted stage. Its thresholds and size rules are still dataset-dependent hyperparameters and should be treated as fixed before inspecting validation results.
- `--eval-split all` is an exploratory whole-dataset run. For `svm_patch`, it includes training images and therefore must not be reported as held-out validation.

## Run

```bash
python scripts/traditional_baselines.py \
  --raw-root datasets/20260512 \
  --processed-root datasets/processed/20260512_tiles_96 \
  --out-dir runs/traditional_baselines \
  --methods imagej_like svm_patch \
  --eval-split internal_val \
  --match-radius 3 \
  --min-distance 2 \
  --save-overlays
```

The processed dataset must contain a `manifest.csv` with `split` and `source_image_id` columns. The run metadata records the selected source-image IDs, command parameters, Python version, and relevant package versions. It does not fingerprint private image contents or establish that two datasets at the same paths are identical.

## Legacy reference values

The following values were carried forward with the baseline restoration and were labeled as results for internal-validation images `4`, `5`, and `18` at a 3-pixel matching radius:

| Method | Class | Precision | Recall | F1 |
|---|---|---:|---:|---:|
| ImageJ-like | 1.0 | 0.7198 | 0.7773 | 0.7475 |
| ImageJ-like | 2.8 | 0.5673 | 0.8725 | 0.6875 |
| SVM patch | 1.0 | 0.6919 | 0.6727 | 0.6822 |
| SVM patch | 2.8 | 0.5393 | 0.8411 | 0.6572 |

These are provenance-only legacy figures: this repository does not include the archived macro/model, dependency lockfile, raw-data fingerprint, or original run artifacts needed to independently reproduce them exactly. They have not been regenerated by this PR and must not be used as an automated acceptance threshold. Reviewers should use a fresh `internal_val` run and retain its `run_metadata.json` with the generated metrics.
